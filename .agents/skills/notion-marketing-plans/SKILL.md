# Private marketing plans in Notion

Keep private marketing plans in Notion and approved public copy in the repository. Read
[AGENTS.md](../../../AGENTS.md#repository-boundary) and [public contributor
safety](../../../docs/public-contributor-safety.md) before saving content.

- For copy-only requests, use [marketing-copy](../marketing-copy/SKILL.md) to edit the locale catalog. Save a plan
  only when the user asks.
- Check Notion tool access and search for an existing plan before creating one. Read before updating; preserve
  unrelated content.
- Use the named destination. Otherwise, create a private draft and return its link. Sharing or moving it to a
  shared page requires user authorization.
- Read Notion's enhanced Markdown specification before writing. Record decisions, proposed copy, evidence, and
  unresolved facts. Distinguish proposals from confirmed services and completed actions.
- Keep plans, subscriber records, campaign schedules, internal metrics, and private Notion links out of tracked
  files, commits, PR descriptions, comments, fixtures, and captures. Public PRs describe the change and validation.
- Keep client data and legal work product in Navigator-managed systems and approved file stores. Do not use client
  records as marketing examples. A plan is a firm planning page: no client names, matter codes, transcript excerpts, or
  anything copied from a Project's private or shared page. See [what Notion
  holds](../../../docs/third-party-integrations.md#what-notion-holds).
- Claiming profiles, subscribing people, sending messages, and publishing campaigns require explicit user
  authorization; saving a plan does not provide it.

Fetch the saved page to verify its contents. When moving a repository plan, verify the Notion save before removing the
file. Preserve approved public copy and check for dangling references. If Notion is unavailable, leave the draft in the
conversation and report it as unsaved.
