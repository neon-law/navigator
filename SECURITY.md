# Security reporting

Send private vulnerability reports to [support@neonlaw.com](mailto:support@neonlaw.com). If GitHub private reporting is
available, you may use it; if it is unavailable or you cannot access it, use that email address. Do not open a public
issue with details of an unresolved vulnerability.

Include the affected version or commit, the component involved, expected and observed behavior, and minimal reproduction
steps using synthetic data. Explain the potential impact and include a suggested fix if you have one.

Do not send credentials, tokens, client data, matter documents, personal information, or production identifiers. If
reproducing the issue requires such material, describe the limitation and ask for a secure reporting arrangement. Test
only systems you own or are authorized to assess.

Coordinate public disclosure with the maintainers after reporting. This policy makes no response-time, remediation,
support, or warranty commitment. The software's warranty disclaimer and limits on liability are in [project
license](LICENSE).
