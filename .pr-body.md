## Why

Navigator has no apparatus for court and program portals — La Superior, PACER, and NYSAF each require a login and return notices in their own format, and documents that arrive by hand bypass triage. The approved Docket Scraper Framework spec locks the architecture: one reusable base framework in the CLI that owns sessions, credentials, retries, resumable downloads, and filing, with each portal written as a thin adapter on top. This PR lands that base. PR #213 already added the `CourtPortal`/`PortalLogin` credential kinds the framework resolves through.

## What

A new `cli/src/scraper/` module:

- **adapter.rs** — the `SiteAdapter` contract: identity, login orchestration hook, notice discovery, and download. Adapters receive an injectable `HttpFetcher` (reqwest-based in production; a scripted test double in tests) and never perform raw network I/O inside parse logic.
- **session.rs** — `BrowserSession` built on Navigator's existing precedents: the pinned Chrome-for-Testing resolver (`cli/src/devx/chrome.rs`) plus fantoccini, with per-site cookie/session persistence between runs and clean shutdown.
- **credentials.rs** — resolves `CourtPortal`/`PortalLogin` logins through the existing `store::resolve_firm_credential` path (one keyed JSON secret per site); a missing row hard-stops before any browser starts with the key to provision named; credentials zeroize on drop and redact in Debug.
- **download.rs** — content-addressed, write-bytes-first resumable downloads: a run that dies mid-file resumes from the last byte offset without re-fetching completed documents, tracked in a ledger.
- **retry.rs** — bounded retries with a doubling, capped backoff behind an injected clock, so tests never wait.
- **intake.rs** — the outbound seam that hands DKT-named documents to the omnichannel inbox (`DKT NNNN - title.ext` via the house `filing_name` module). For this PR the seam ships with test doubles and an explicit unwired production placeholder — the real inbox integration is a later task.
- **mod.rs** — orchestration: resolve credential → open session → login → discover → download → enqueue. Run state persists so runs restart; transient failures retry with backoff; credential or site-structure failures hard-stop with a named error and file nothing.

`navigator scraper sites` and `navigator scraper run --site … --docket …` follow the house clap pattern. No adapters are registered yet — the La Superior adapter is the next PR.

## How to Review

- Start with `cli/src/scraper/adapter.rs` (the seam) and `cli/src/scraper/mod.rs` (the run state machine).
- `store/` is untouched (`git diff origin/main...HEAD -- store/` is empty); the credential kinds come from PR #213, so no caller-inventory regeneration is needed.
- The `navigator.yaml` `scrapers:` key is deferred to the adapter PR: the manifest accepts a closed key set and nothing consumes scraper config yet.
- With no registered adapters and no real inbox wiring yet, adapter-facing surfaces carry the repo's `cfg_attr(not(test), allow(dead_code))` pattern rather than dying under the workspace's deny-dead-code lint.
